# 🏛️ 뭐먹지? (WhatEat) 서비스 기능명세서

본 문서는 식단 관리, 맛집 탐색, 커뮤니티 투표 등을 종합 제공하는 '뭐먹지?(WhatEat)' 서비스의 전체 메뉴 구조와 기능 스펙을 명확히 설명한 공식 기능 명세서입니다.

---

## 📱 서비스 전체 메뉴 구조 및 핵심 기능

### 1. 나만의 맛집 서랍장 (Solo)
개인화된 맛집 일지와 약속, 캘린더를 통해 자신의 모든 식생활 기록을 축적하고 관리하는 완전 프라이빗 공간입니다.
솔로 탭은 **오롯이 본인만의 식사 일기장**으로, 가족이나 타인과 자동으로 공유되지 않습니다.

#### 탭 구조
솔로 탭 상단에 `먹로그 / 먹예약 / 먹캘린더` 3개 서브탭이 제공됩니다.

---

#### ① 먹로그 (Meal Log)
- **개요:** 사용자가 일자별, 식사 시간대별(아침, 점심, 저녁)로 먹은 음식을 이미지와 함께 간편히 기록합니다.
- **데이터 저장 전략 (DB-first):**
  - **모든 식사 기록은 처음 등록 시점부터 즉시 Supabase `meal_images` 테이블에 저장**됩니다. localStorage, sessionStorage 등 클라이언트 저장소는 일절 사용하지 않습니다.
  - 이미지 업로드 → AI 분석 → 메뉴명 입력 → 저장 전 과정이 모두 DB 기반으로 처리됩니다.
  - `source` 컬럼 값: 솔로 먹로그 등록 시 `'solo'`로 설정되어, 패밀리/맛톡 피드와 명확히 구분됩니다.
- **이미지 첨부 및 로컬 압축 (WebP 1024px 규격 통일):**
  - 사용자가 업로드하는 원본 이미지는 클라이언트 브라우저 단(Canvas API)에서 실시간으로 최대 1024px 해상도의 WebP 포맷(품질 75%)으로 압축 처리됩니다.
  - 이를 통해 원본 이미지 대비 약 98%의 용량을 획기적으로 절감(장당 평균 70KB 내외)하여 네트워크 대역폭 절약 및 고속 업로드가 가능하며, 백엔드/스토리지 저장 효율을 극대화합니다.
- **AI 메뉴명 추천 기능:**
  - 이미지 업로드 즉시 클라이언트 백엔드 비동기 통신(`/api/ai/analyze-food-image`)을 수행합니다.
  - OpenAI의 `gpt-4o-mini` API를 기반으로, 첨부된 음식 사진을 분석해 정확한 요리 이름을 식별한 뒤 메뉴명 입력란에 자동으로 채워 줍니다.
  - 분석 중일 때는 "AI가 사진을 분석하고 있어요..."라는 전용 로딩 인디케이터가 표출됩니다.
  - 사용자는 AI가 추천해 준 메뉴명을 자유롭게 수정하여 최종 등록할 수 있습니다.
- **식사 카드 레이아웃 (좌우 분할 카드):**
  - 각 식사 카드는 **좌측(이미지 50%) + 우측(정보 50%)** 수평 분할 레이아웃으로 표시됩니다.
  - 좌측: 식사 사진(hover 시 scale-105), 식사 유형 배지(집밥/배달/외식), AI 태그, HEALTHY 배지
  - 우측: 레시피 링크 썸네일 또는 직접 작성한 팁/메모
  - 하단: 날짜, 별점, 메뉴명, 댓글 섹션
  - 카드 그리드: 모바일 1열, 데스크탑 2열 (`grid-cols-1 lg:grid-cols-2`)
  - 카드 모서리: `rounded-[2rem]`
- **초기 진입 샘플 노출 및 타입별 개별 소멸:**
  - 등록된 식사 일지 데이터가 전혀 없는 초기 진입 시 샘플 식사 일지(집밥, 배달, 외식 각 1개씩 총 3개)가 기본 노출됩니다.
  - 사용자가 특정 식생활 유형의 식사 기록을 등록하면 해당 유형의 샘플 카드만 골라서 소멸합니다. 배달과 외식도 각각 독립적으로 소멸합니다.
- **식사 카드 수정/삭제 UX 및 모달 타이틀:**
  - 식사 기록 등록 및 수정 모달 진입 시, 타이틀은 `(솔로) 먹로그 기록하기` 혹은 `(솔로) 먹로그 수정하기`로 표기되어 패밀리 모달과 시각적으로 구분됩니다.
  - 카드 우측 상단에 수정(연필) 아이콘만 단일 노출되며, 항상 흰색 반투명 둥근 배경으로 시인성을 보장합니다.
  - 삭제 액션은 수정 모달 내부의 [쓰레기통] 삭제 버튼으로 이관합니다.
  - 샘플 카드 삭제 시 "식사를 등록하면 샘플은 바로 사라집니다." 토스트 가이드를 표시하며 수정 모달은 유지됩니다.
- **실시간 GPS 기반 외식 장소 자동 검색 (v2.3 추가):**
  - 외식(dineout) 식사 등록 시, 하드코딩된 목업 식당 목록 대신 브라우저의 Geolocation API를 통해 사용자의 현재 위도/경도를 획득합니다.
  - 획득한 위경도로 OpenStreetMap Nominatim reverse geocoding API를 통해 행정동(예: 청라동)을 분석한 후, 모바일 네이버 검색 결과를 실시간으로 파싱하여 실제 운영 중인 반경 내 맛집 목록(식당명, 업태 카테고리, 도로명 주소 및 대표 음식 썸네일 이미지)을 동적으로 로드 및 매핑합니다.
- **레시피 및 식당 외부 링크 미리보기 카드 세분화 (v2.3 추가):**
  - 식사 카드 우측 영역의 링크 박스 디자인을 세분화했습니다. Kakao/Google/Naver Map/Place 등의 지도 링크는 각 플랫폼별 색상 테마 및 고유 아이콘(`Map` / `Place`)으로 맞춤 표시됩니다.
  - YouTube, Instagram, TikTok 영상 링크 또한 각 플랫폼별 대표 컬러가 적용된 전용 카드 형태로 표시됩니다.
  - 그 외의 일반 외부 링크는 집밥의 경우 `"레시피 (Recipe / R)"`, 외식/배달의 경우 `"식당 링크 (Link / P)"`로 고도화 분류되어 렌더링됩니다.

#### ② 댓글 기능 (혼자 쓰는 메모형 댓글)
- **개요:** 솔로 먹로그의 각 식사 카드에 댓글을 달 수 있습니다. 솔로에서의 댓글은 본인만 보는 메모 형태이며, 나중에 가족방이나 맛톡에서 다른 사람들이 이어서 작성하는 구조로 연결됩니다.
- **저장:** 댓글은 Supabase `comments` 테이블에 저장됩니다. (localStorage 사용 없음)
- **댓글 UI 스펙 (패밀리와 완전 통일):**
  - 댓글 버블: `rounded-xl bg-orange-50/50 border border-orange-100 p-2.5`
  - 헤더: 작성자명(굵게) + 작성 시각(우측 정렬)
  - 액션 버튼: 하트(❤️) 좋아요 카운트 + `답글` 버튼 (패밀리와 동일 레이아웃)
  - 대댓글: 좌측 `border-l-2 border-orange-200` 들여쓰기
  - 입력창: `bg-gray-50 border-gray-200 rounded-lg` + 주황색 Send 아이콘 버튼

#### ③ 먹예약 (Reservation)
- **개요:** 지인, 가족 혹은 나만의 식사 약속 일정을 사전 기입하여 예약 현황을 한눈에 관리합니다.
- **기능 스펙:** 약속 날짜, 시간, 장소(식당명), 함께 식사할 인원 정보 등을 상세히 등록하고 조회합니다.
- **초기 진입 샘플 날짜 동적 스케줄링**:
  - 사용자가 먹예약 탭에 최초 진입하는 시점의 날짜를 기준값으로 삼아, **다음 달 초/중순의 날짜로 예약 샘플 날짜가 동적으로 생성**됩니다.
  - **주중(월~금) 조건**: 집밥(파스타) - 다음 달 5일 기준 가장 가까운 주중 / 배달(치킨) - 다음 달 12일 기준 가장 가까운 주중
  - **주말(토~일) 조건**: 외식(삼겹살) - 다음 달 10일 기준 가장 가까운 주말
  - 한 번 계산된 날짜는 `localStorage`(`whateat_reservation_plans` 키)에 저장 및 유지되므로 재진입 시 변하지 않습니다.
  - 달력 컴포넌트의 최초 화면 연월(`currentMonth`) 역시 접속 시점의 시스템 연월에 연계되어 동적 초기화됩니다.
- **샘플 데이터 수정 제한**:
  - 샘플 예약 정보(ID 1, 2, 3)는 수정 모달에서 수정을 시도하여 저장을 완료하려 할 때 **"샘플이라 수정이 되지 않습니다."** 경고 토스트 알림을 제공하고 폼 제출을 철저히 차단합니다.
  - 데이터 저장 함수(`handleModalSave`) 레벨에서도 대상 ID 1, 2, 3을 차단해 이중 안전장치를 구현했습니다.

#### ④ 먹캘린더 (Meal Calendar)
- **개요:** 월간 달력 뷰를 기반으로 한 달간의 식사 이력을 시각적으로 일목요연하게 제공합니다.
- **기능 스펙:**
  - 캘린더 날짜 클릭 시 해당 일자의 식사 기록으로 바로 점프하는 연동 기능이 내장됩니다.
  - 날짜 셀에는 썸네일 없이 메뉴명 텍스트 칩만 표시합니다. (셀이 너무 작아 썸네일 불가)
  - 예약된 날짜는 별도 색상 배지로 구분됩니다.

### 2. 가족 식탁의 즐거움 (Family)
가족 구성원들이 함께 식사를 기록·공유·투표하는 공동 공간입니다.
**솔로와 패밀리는 완전히 분리**되어 있으며, 솔로 먹로그의 내용은 패밀리에 자동으로 노출되지 않습니다.
가족 식사는 처음부터 패밀리 탭에서 직접 등록하는 방식을 원칙으로 합니다.

#### 탭 구조 (솔로와 동일)
패밀리 탭 상단에 `먹로그 / 먹예약 / 먹캘린더` 3개 서브탭이 제공됩니다.

---

#### ① 먹로그 — 공유된 가족 식사 피드
- **개요:** 가족방에서 직접 등록된 식사 카드만 표시합니다. 솔로에서 등록된 식사는 이 피드에 절대 표시되지 않습니다.
  - DB 쿼리 조건: `source = 'family-shared'` (솔로 `source: 'solo'` 및 기타 소스 일체 제외)
- **식사 카드 레이아웃 (솔로와 동일):**
  - 각 식사 카드는 **좌측(이미지 50%) + 우측(정보 50%)** 수평 분할 레이아웃 (`h-190px`)
  - 좌측: 사진 배경 + 그라데이션 오버레이 + 식사 유형 배지(집밥/배달/외식/기타)
  - 우측: 메뉴명, 등록자(sharedBy), 등록 시각, 홈쉐퍼 배지, 별점 평균
  - 하단: 댓글 토글 버튼 (클릭 시 댓글 목록 펼침/접힘)
  - 카드 그리드: 모바일 1열, 데스크탑 2열 (`grid-cols-1 lg:grid-cols-2`)
  - 카드 모서리: `rounded-[2rem]` (솔로와 동일)
- **식사 직접 등록 및 모달 타이틀:**
  - 우측 하단의 (+) 버튼을 활용해 가족 먹로그에 식사를 즉시 기록하여 공유할 수 있습니다.
  - 솔로 탭의 `AddLogModal` 입력을 공용으로 제공하며, 등록 즉시 `source = 'family-shared'` 데이터로 반영되어 실시간으로 공유됩니다.
  - 등록 및 수정 모달 진입 시 타이틀은 `(패밀리) 먹로그 기록하기` 혹은 `(패밀리) 먹로그 수정하기`로 노출되어 솔로 모달과 명확하게 구분됩니다.
- **별점 시스템:**
  - 각 식사는 별점 평가 기간(마감 기한)이 설정됩니다.
  - 평가 기간 중(isOpen=true): 카드 클릭 시 별점 입력 모달이 열립니다. 가족 구성원 1인당 1회 평가 가능.
  - 평가 마감 후(isOpen=false): 카드 클릭 대신 댓글 토글로 대체됩니다.
  - 평균 별점은 카드 우측 하단에 상시 표시됩니다.
- **초기 진입 샘플 노출:** 공유된 가족 식사 데이터가 없을 경우 가상의 샘플 식사 카드와 가이드용 댓글이 노출됩니다. 실 데이터 등록 시 전환됩니다.

#### ② 먹예약 — 투표 + Chef's Choice 통합 탭
- **개요:** 가족 식사 예약과 메뉴 투표를 한 화면에서 관리합니다.
- **탭 상단 투표 배지:**
  - 진행 중인 이번 주 식사 투표가 있을 때 탭 최상단에 🗳️ 주황색 투표 배지가 표시됩니다.
  - 배지에는 투표 제목이 표시되어 현재 어떤 투표가 진행 중인지 즉시 파악 가능합니다.
- **메뉴 공동 투표:**
  - "오늘 저녁 뭐 먹지?" 등 결정하기 어려울 때 식구들이 함께 메뉴 후보군을 설정해 투표를 진행합니다.
  - 가족 구성원들은 실시간으로 후보 메뉴에 한 표씩 행사하며 실시간 득표수가 반영됩니다.
  - 비로그인 상태에서는 투표 참여 및 만들기 시 로그인 창이 노출됩니다.
- **Chef's Choice (오늘의 메뉴 결정):**
  - 셰프로 지정된 구성원이 오늘의 아침/점심/저녁 메뉴를 최종 확정합니다.
  - 결정된 메뉴는 Supabase `meal_menus` 테이블에 저장되어 가족 구성원에게 동기화됩니다.
  - 메뉴가 결정되면 해당 시간대 샘플 메뉴가 실제 확정 메뉴로 교체됩니다.
  - 먹예약 탭 내에서 투표 카드와 Chef's Choice 섹션이 스크롤로 이어집니다.

#### ③ 먹캘린더 — 가족 식사 달력
- **개요:** 월간 달력 뷰로 가족의 식사 이력을 시각적으로 제공합니다.
- **기능 스펙:**
  - 날짜 셀에 메뉴명 텍스트 칩 표시 (썸네일 없음 — 솔로 캘린더와 동일 원칙)
  - 투표 진행 중인 날짜에는 🗳️ 투표 칩이 함께 표시됩니다.
  - 날짜 클릭 시 먹로그/먹예약 탭으로 이동 가능(양방향 접근)

#### ④ 댓글 기능 (가족 소통)
- **저장:** Supabase `comments` 테이블에 저장됩니다.
- **댓글 UI 스펙 (솔로와 완전 통일):**
  - 댓글 버블: `rounded-xl bg-orange-50/50 border border-orange-100 p-2.5`
  - 헤더: 작성자명 + 작성 시각
  - 액션 버튼: 하트(❤️) 좋아요 카운트 + `답글` 버튼
  - 대댓글: 좌측 들여쓰기 + border-l 구분선
  - 입력창: `bg-gray-50 border-gray-200 rounded-lg` + 주황색 Send 아이콘 버튼
  - **솔로(개인 메모) → 패밀리/맛톡(가족 소통)으로 이어지는 댓글 연속성이 핵심 컨셉입니다.**

#### ⑤ 우리가족 셰프 지정 및 메뉴 결정 권한
- **개요:** 가족들의 식사를 결정하고 가이드할 주방 책임자(셰프)를 지정합니다.
- **기능 스펙:** 
  - 방장(가족 개설자)은 구성원 중 1명을 '셰프'로 선정할 수 있습니다. 셰프는 프로필 우상단에 노란색 ChefHat 배지가 표시됩니다.
  - 셰프는 오늘의 아침/점심/저녁 메뉴를 최종 확정할 수 있는 **메뉴 결정 권한**을 가집니다. (식단 등록 권한은 제외됩니다.)
  - 결정된 오늘의 메뉴 정보는 즉각 Supabase `meal_menus` 테이블(school_code='family', kcal=결정자닉네임, is_temporary=false)에 저장됩니다.

#### ⑥ 동적 가족 구성원 관리 (가상 플레이스홀더 청소)
- **기능 스펙:**
  - 비로그인 상태이거나 초대한 가족이 아직 없는 초기 상태에는 가상 가족 플레이스홀더(엄마, 아빠, 동생)가 기본 구성원으로 노출됩니다.
  - **진짜 가족(초대 이력 중 `REWARDED` 상태가 된 구성원)이 1명이라도 생기는 즉시**, 가상 플레이스홀더는 완전히 제거되고 "나"와 "진짜 가입한 가족 멤버"들로만 구성원 카드가 갱신됩니다.
  - 구성원 갱신 시 기존 셰프 역할이 안전하게 유지 및 승계되도록 자동 매핑 예외 처리가 반영됩니다.

#### ⑦ 비로그인(게스트) 접근 제한 및 로그인 유도
- **기능 스펙:**
  - 비로그인 게스트는 공유된 식사, 오늘의 메뉴 현황, 진행 중인 투표를 자유롭게 조회할 수 있으나, 투표 작성/참여, 메뉴 최종 결정, 가족 사진 업로드, 셰프 지정 등 데이터를 변경하는 동작을 시도할 경우 즉시 로그인 창으로 유도합니다.
  - 온보딩 카드 우상단에 닫기(X) 버튼을 제공합니다. 사용자가 닫으면 세션 스토리지에 기록하여 오늘 세션 동안 온보딩 카드가 노출되지 않도록 처리합니다.

#### ⑧ 가족 초대 및 합류 확인 모달 (Join Family Flow)
- **기능 스펙:**
  - 피초대자가 가족 초대 URL을 통해 서비스에 진입하고 가입/로그인을 완료하면, 가족 합류 확인 모달이 자동으로 표출됩니다.
  - 피초대자가 합류를 '수락'하면 대기 상태가 되며, 패밀리 방의 방장이 승인 처리를 완료하여 상태가 `REWARDED`로 업데이트되어야만 정식 가족으로 구성원 목록에 노출됩니다.

### 3. 동네 찐 맛집 발견 (Talk)
사용자가 등록한 실주소/학교 지역 기반으로 신뢰도 높은 이웃들이 직접 작성한 진짜 맛집 정보들만 엄선해 보여주는 필터링 정보 공간입니다.

#### ① 광고 없는 이웃 리뷰
- **개요:** 대행사 광고나 바이럴 포스팅이 전혀 없는, 같은 행정구역 및 학교 인근의 주민들이 순수하게 작성한 리뷰만 보여줍니다.
- **정렬 및 검색:** 5점 만점 평점 평균순, 최다 리뷰 등록순 등으로 동네 찐 맛집 순위를 다이나믹하게 필터링하여 사용자에게 맞춤 추천합니다.
- **실시간 맛톡 연동 및 등록 일시:**
  - 솔로/패밀리 식사 일지에서 **누구라도 5점을 부여하고 공개를 승낙하는 즉시** 해당 게시글이 맛톡 피드에 노출(`status: 'approved'`)됩니다.
  - 피드에 노출되는 최초 작성자(author)는 솔로 식사일 경우 이미지 업로더의 닉네임과 프로필로 설정되지만, **패밀리 식사일 경우 해당 식사를 공유한 가족의 이름(예: `[방장닉네임] 가족`)**으로 자동 갱신 및 결합하여 맛톡에 표시됩니다. (가족 방장의 닉네임은 `referrals` 추천 관계 테이블을 추적하여 동적으로 획득합니다.)
  - 맛톡 피드에 표시되는 등록 일시는 식사가 최초 작성된 시각이 아니라, **맛톡에 최종 승격되어 연동된 시점의 일시**로 표기됩니다.
- **맛톡 중복 승격 방지 및 실시간 별점 누적:**
  - 가족 및 모임 식사의 경우, 한 구성원에 의해 이미 맛톡으로 승격(`status: 'approved'`)되었다면 **다른 구성원이 추가로 별점을 매기더라도 맛톡 피드에 게시글이 중복 생성되지 않고** 단일 게시물로 유지됩니다.
  - 이후에 등록되는 평가는 누적되어 실시간 평점 평균(Rating Average) 및 평가 참여자 수에 정상 합산되어 반영됩니다.
  - **별점 세부 정보 표시:** 맛톡 피드에 노출되는 식사는 최초 등재 유형(소스: 솔로, 가족, 모임)과 평점 평균 및 평가 참여자 수를 한눈에 볼 수 있도록 정보를 구분하여 표시합니다.
    - 예시: `5.0 (1명) 솔로`, `4.0 (3명) 가족`, `4.2 (7명) 모임`
  - 1인당 한 식사에 대해 별점을 매기는 행위는 단 1회로 제한됩니다.

#### ② 맛톡 카드 액션 (좋아요 / 댓글 / 담기)
- **좋아요:** 이웃이 등록된 맛집 피드 글에 대해 공감 반응을 보낼 수 있습니다.
- **댓글:** 맛톡 피드 글 하단에 댓글 및 답글(대댓글)을 작성하여 소통할 수 있습니다.
- **담기 및 먹예약 자동 연동:** 
  - 맛톡 피드의 식사 기록을 자신의 개인(솔로) 또는 가족 공간으로 수집하는 기능입니다.
  - 맛톡 카드에서 `담기`를 실행하여 **`👤 솔로 먹예약`** 또는 **`👨‍👩‍👧 가족 먹예약`** 중 하나를 선택합니다.
  - 선택 즉시 해당 탭(솔로 또는 가족)의 **먹예약 탭으로 화면이 즉시 전환**되고, 예약 등록 모달이 자동으로 활성화됩니다.
  - 활성화된 예약 모달에는 가져오고자 한 맛톡 카드의 **메뉴명, 식사 유형(집밥/배달/외식), 식당명(외식/배달의 경우)**이 **자동 완성(Pre-filled)** 상태로 설정되며, 사용자는 상세 일시(날짜, 시간)만 기입하여 손쉽게 예약 처리를 끝낼 수 있습니다.
  - 맛톡 카드를 담아갈 때, 해당 게시물에 **자동으로 '좋아요'가 눌리도록 강제 처리**합니다 (중복 클릭 방지 처리가 적용되어 이미 좋아요 상태라면 카운트가 이중 증가하지 않습니다).

#### ③ 맛톡 연동 및 자동 처리 안내 UX (v2.3 추가)
- **공개 동의 모달**: 5점 별점을 최초로 부여하여 맛톡에 등록할 때, "맛톡 공개 동의" 모달창이 활성화되어 공개 허용 여부를 수집합니다.
- **자동 공유 시 안내 토스트 제공**: 모달창에서 '이후 항상 이 선택 적용(자동 처리)'을 선택하여 승낙(approved)해 둔 경우, 다음부터는 공개 동의 모달이 팝업되는 대신 `"5점 별점 식사가 맛톡 동네 피드에 자동 공유되었습니다!"` ✨ 안내 토스트 메시지가 노출되고, 1.5초간의 시각적 대기 시간을 준 뒤 맛톡 동네 피드로 부드럽게 화면을 전환시킵니다.

#### ④ 맛톡 공유 기록 회수 및 차단 정책 (v2.3 추가)
- **이웃 활동 미발생 시 자동 수거**: 맛톡 피드에 공유된 5점 식사 기록에 대해 타인의 활동(댓글 등)이 전혀 발생하지 않은 상태에서 작성자가 별점을 4점 이하로 낮추거나 기록을 수정하면, `"다른 유저의 활동이 없어 맛톡 피드에서 식사 기록을 수거했습니다."` 🧹 토스트와 함께 해당 식사는 맛톡 피드에서 즉각 내려갑니다 (status가 'pending'으로 안전하게 강등 조정됩니다).
- **이웃 활동 발생 시 수거 차단**: 다른 이웃의 댓글 등 실제 유저 활동이 이미 발생한 식사 글인 경우, 작성자가 평점을 4점 이하로 낮추어 수거하는 행위를 엄격히 차단합니다. 변경 시도 시 `"다른 이웃의 댓글 등 활동이 발생하여 맛톡에서 식사 기록을 회수할 수 없습니다."` 🔒 경고 토스트를 노출하며, 평점을 기존의 5점 및 'approved' 상태로 자동 복원합니다.

### 4. 우리 아이 학교 급식 (School)
초·중·고등학생 자녀를 둔 학부모와 학생들이 매일의 학교 급식 메뉴를 체크하고 평점을 남기며 학습형 미니게임을 즐기는 공간입니다.

#### ① 급식 메뉴 확인 & 평가
- **개요:** 교육행정정보시스템(NEIS) API를 연동하여 등록된 학교의 당일 식단 정보(메뉴 목록, 칼로리, 알레르기 유발 정보, 원산지 정보)를 정확하게 노출합니다.
- **기능 스펙:** 
  - 학교를 등록하지 않았거나 등록된 학교의 당일 급식 데이터가 부재한 경우, 기본 플레이스홀더 성격의 가상 샘플 급식 정보가 예쁘게 구성되어 나타납니다.
  - 사용자가 급식에 대해 직접 평점을 매기거나 댓글을 작성하여 남들과 소통할 수 있는 직관적인 피드백 구조를 제공합니다.

#### ② 식단 연계 AI 퀴즈
- **개요:** 당일 급식 식단 재료와 영양성분을 연동하여 생성된 미니 영양 퀴즈를 풀어보는 재미있는 상식 퀴즈 게임입니다.
- **기능 스펙:** 
  - 실제 당일 급식 식재료 정보에 입각하여 AI 영양 퀴즈가 실시간 생성됩니다.
  - 퀴즈 정답 제출 시 상세하고 친절한 AI 영양 상식 해설 피드백이 제공됩니다.
  - 정답 획득에 성공할 때마다 개인 퀴즈 이력이 누적되어, 명예의 전당에 챔피언 자격으로 이름을 올릴 수 있는 성취 요소를 포함합니다.

### 5. 프로필 및 앱 초대 (Profile)
통합 허브 계정 정보 조회, 초대 실적 리스트, 그리고 전반적인 계정 알림 및 동기화 설정을 수행하는 단독 공간입니다.

#### ① 앱 초대 실적 관리 (앱 초대 List)
- **개요:** 내 추천 코드를 타고 서비스에 진입해 회원가입을 거쳐 정식 이벤트를 완수한 친구들의 누적 가입 실적을 관리합니다.
- **기능 스펙:**
  - 코인이 존재하지 않는 왓잇 서비스 스펙에 맞춰, 보상 획득을 뜻하는 기존 `지급 완료` 뱃지 대신 **`초대 성공`** 뱃지를 달아 코인 용어를 완전히 순화했습니다.
  - 초대 링크를 타고 회원 가입을 시작하였으나 아직 정식 회원 조건(가족 수락 등)을 채우지 않은 대기 중인 유저의 진행 현황도 초대자가 파악할 수 있도록 **`대기 중 (조건 미달성)`** 배지를 실적 리스트에 정상 복구하여 표시해 줍니다.

#### ② 헤더 탭 하이라이트 배제 및 해시 갱신 네비게이션
- **기능 스펙:**
  - 프로필 설정 페이지(`/profile`) 진입 시 헤더의 4대 탭(솔로, 패밀리, 맛톡, 급식) 중 어느 것도 활성화되지 않도록 `activeNavTab` 프로프 값을 `null`로 강제 매핑합니다.
  - 프로필 헤더에서 다른 탭 클릭 시 로컬스토리지를 거치지 않고 Next.js 라우터 해시(`/#[탭명]`)로 즉각 이동합니다.
  - 메인 컴포넌트(`WhatEatApp`)의 `hashchange` 이벤트 리스너를 결합하여, 프로필을 이탈해 복귀하는 첫 번째 터치만으로 딜레이 없이 해당하는 메인 탭으로 원활하게 전환되도록 네비게이션 경험을 강화했습니다.

## 📐 공통 UI 원칙

### 식사 카드 레이아웃 (솔로 & 패밀리 공통)
- **좌우 분할 구조:** 모든 식사 카드는 이미지(좌) + 정보(우) 50:50 수평 분할
- **카드 높이:** `h-[190px]` ~ `h-[200px]` 고정
- **카드 모서리:** `rounded-[2rem]` (부드러운 대형 radius)
- **이미지 처리:** `bg-cover bg-center` + hover 시 `scale-105` + 그라데이션 오버레이

## 🗄️ 데이터 저장 전략

### 전체 원칙: DB-first (localStorage 사용 금지)
- **모든 사용자 데이터는 처음 등록 시점부터 즉시 Supabase DB에 저장**합니다.
- localStorage, sessionStorage 등 클라이언트 저장소는 세션 내 일시적 UI 상태(온보딩 닫기 여부 등) 용도로만 제한적으로 사용하며, 실제 식사 데이터·댓글·별점은 일절 클라이언트에 저장하지 않습니다.
- **클라이언트 직접 쓰기 차단 (RLS 준수)**: 클라이언트에서 Supabase JS SDK를 통해 직접 DB에 쓰거나(insert/update/delete) 스토리지를 조작하는 것을 금지하며, 모든 쓰기/업로드 작업은 인증 필터링이 적용된 안전한 백엔드 API 라우트를 통해 대행합니다.

### 데이터베이스/스토리지 보안 API 개요
* **DB 보안 쓰기 API (`/api/db/write`)**: 
  * 프론트엔드의 `secureWrite` 헬퍼를 통해 호출되며, 요청 헤더의 Merlin Hub JWT 토큰을 검증해 사용자 식별자를 획득합니다.
  * `uploaded_by`, `user_id` 등 소유자 검증을 거쳐 본인의 레코드만 생성/수정/삭제하도록 안전하게 처리한 뒤 `supabaseAdmin` 권한으로 실행합니다.
* **스토리지 보안 업로드 API (`/api/db/upload-image`)**:
  * Merlin Hub 토큰 검증을 통과한 사용자만 base64 형식의 이미지 파일과 파일명을 전송하여 호출합니다.
  * 서버에서 base64를 디코딩하여 스토리지의 `meal-images` 버킷에 `supabaseAdmin`으로 업로드하고 공개 URL을 반환합니다.

### 주요 테이블 및 source 구분
| 테이블 | 용도 | source 값 |
|---|---|---|
| `meal_images` | 식사 이미지 기록 | `'solo'` (솔로) / `'family-shared'` (패밀리) |
| `comments` | 댓글 (솔로·패밀리·맛톡 공용) | meal_image_id 기반 참조 |
| `meal_ratings` | 별점 (가족 구성원별 1회) | meal_image_id 기반 참조 |
| `meal_menus` | 셰프가 결정한 오늘의 메뉴 | `school_code='family'` |

### 이미지 업로드 파이프라인
* **솔로 및 패밀리 식로그 이미지**:
  1. 클라이언트 Canvas API로 WebP 1024px 75% 품질 압축 (업로드 전)
  2. `/api/db/upload-image` → Supabase Storage 저장 및 공개 URL 반환 (서버 대행)
  3. `/api/db/write` (action: 'insert') → `meal_images` 테이블에 메타데이터 기록 (서버 대행)
* **급식 이미지 (학교 배틀 모드)**:
  1. 클라이언트 Canvas API로 WebP 1024px 75% 품질 압축 (업로드 전)
  2. `/api/meal-images/upload` → Supabase Storage 저장
  3. `/api/meal-images/create` → `meal_images` 테이블에 메타데이터 기록
  4. `/api/ai/analyze-food-image` → 비동기 AI 메뉴명 분석 (gpt-4o-mini)
  5. 맛톡 승격 조건: 5점 부여 + 공개 동의 → `status: 'approved'` 업데이트

### 데이터베이스 보안 및 예외 진단 정책 (v2.2 추가)
- **보안 설정 및 확장 기능 최적화**:
  - 프로젝트에서 사용하지 않는 `pg_graphql` 확장 기능을 비활성화하여 외부 스키마 및 테이블 구조 노출 위험을 원천 차단했습니다.
  - `SECURITY DEFINER` 함수(`get_menu_item_rating_stats`, `update_menu_item_rating_stats`, `update_school_rating_stats`)의 외부 `EXECUTE` 권한을 회수(REVOKE)하고, 오직 DB 내부 트리거 및 `postgres`, `service_role` 권한으로만 실행을 허용하여 클라이언트 단의 무분별한 RPC 실행을 봉쇄했습니다.
- **실시간 예외 진단 구조 고도화**:
  - 프론트엔드(`MealLogTab`, `FamilyPage` 등)에서 데이터베이스 저장 및 이미지 업로드 예외 발생 시, 하드코딩된 에러 메시지 대신 **실제 서버 응답 및 네트워크 예외 문구를 토스트 알림에 노출**하도록 개선했습니다. 이를 통해 세션 만료, 권한 오류, 배포 서버 환경변수 누락 등의 문제를 운영 중에 실시간으로 진단 가능하도록 보완했습니다.

## 🚀 아키텍처 개편 및 최적화 미션 (Future Work)

#### ① 사용자 정보 테이블 통합 및 school_infos 단일화 검토
- **개요:** 자녀들의 급식 연동용 기초 정보로 인해 별도 테이블로 파편화된 `school_infos` 테이블을 장기적으로 개편하고 단순화합니다.
- **기능 미션:**
  - 향후 급식 테이블 마스터 개편 시, 별도의 `school_infos` 매핑 테이블을 완전히 삭제하고 `users` 테이블 내에 학생 여부(`is_student`), 학교명(`school_name`), 학년(`grade`) 컬럼을 직접 병합하여 단일 테이블 형태로 관리하는 방안의 타당성을 조사합니다.
  - 이를 통해 회원 관리 및 학교/지역 매핑에 대한 RLS 정책과 DB 조회 비연합(N+1 문제 등) 비효율성을 근본적으로 제거합니다.

#### ② 패밀리 먹캘린더 가족 데이터 연동
- 현재 패밀리 먹캘린더는 `MealCalendarTab` 컴포넌트를 솔로와 공유합니다.
- 향후 패밀리 전용 `family-shared` 기반 달력 데이터를 분리하여 솔로와 패밀리 캘린더가 각각 독립적인 데이터 소스를 갖도록 개선합니다.

#### ③ 패밀리 먹예약 탭 — 실제 예약 기능 추가
- 현재 먹예약 탭은 투표+메뉴결정을 통합한 구조입니다.
- 향후 가족 단위 식사 예약(날짜/장소/인원) 등록 기능을 추가하여 예약 리스트와 투표가 함께 표시되도록 합니다.

#### ④ 맛톡 피드 — 반응 없는 게시물 자동 소멸 정책 (콘텐츠 품질 유지)
- **배경 및 목적:** 맛톡 피드에 등록된 5점 만점 게시물 중, 장기간 좋아요 등의 피드백 반응이 없는 저품질/비인기 게시물을 자동으로 소멸시켜 동네 찐 맛집 피드의 콘텐츠 신선도와 품질을 유지합니다.
- **소멸 기준:**
  - 5점 획득으로 맛톡에 승격된 카드가 노출된 이후, **일정 기간(예: 30일/90일) 동안 좋아요 반응이 기준치 미만(예: 0개 또는 1개 미만)**인 게시물은 맛톡 피드(`status: 'approved'`)에서 자동 소멸(`status: 'expired'`) 처리합니다.
  - 소멸 처리 시, 원작성자의 개인 솔로/가족 먹로그 내에 저장된 원본 데이터에는 아무런 영향을 주지 않고 안전하게 보존됩니다.
- **초기 유예 기간 적용 (유저 모집용):**
  - **서비스 론칭 초반에는 유저 수가 부족하므로 자동 소멸 기능을 비활성화** 상태로 시작합니다.
  - 인원이 충족되는 시점(예: 출시 후 약 반년/6개월 내외)까지는 그대로 노출을 유지하고, 활성화 타겟 시점에 환경변수(`TALK_AUTO_EXPIRE_ENABLED`)를 통해 기능을 즉시 활성화합니다.

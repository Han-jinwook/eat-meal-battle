# 🏛️ 뭐먹지? (WhatEat) 서비스 기능명세서

본 문서는 식단 관리, 맛집 탐색, 커뮤니티 투표 등을 종합 제공하는 '뭐먹지?(WhatEat)' 서비스의 전체 메뉴 구조와 기능 스펙을 명확히 설명한 공식 기능 명세서입니다.

---

## 📱 서비스 전체 메뉴 구조 및 핵심 기능

### 0. 공통 기능 (Header)
- **통합 검색 시스템 (v2.5 추가):**
  - 헤더 우측의 돋보기 아이콘을 클릭하여 활성화되는 다이나믹 검색창입니다.
  - 현재 활성화된 탭(솔로, 패밀리, 맛톡 등)과 **독립적으로, 서비스 전체의 데이터(메뉴명, 식당명, 설명, 메모 등)를 아우르는 통합 검색**을 지원합니다.
  - 검색창 입력 시 자동으로 결과가 필터링되어 나타나며, 검색 중일 때는 드롭다운(자동완성) 메뉴가 노출되지 않도록 고도화되었습니다.
  - 검색창 닫기 시 기존 화면으로 복귀합니다.

### 1. 나만의 맛집 서랍장 (Solo)
개인화된 맛집 일지와 약속, 캘린더를 통해 자신의 모든 식생활 기록을 축적하고 관리하는 완전 프라이빗 공간입니다.
솔로 탭은 **오롯이 본인만의 식사 일기장**으로, 가족이나 타인과 자동으로 공유되지 않습니다.

#### 탭 구조
솔로 탭 상단에 `먹로그 / 먹예약 / 먹캘린더` 3개 서브탭이 제공됩니다.

---

#### ① 먹로그 (Meal Log)
- **개요:** 사용자가 일자별, 식사 시간대별(아침, 점심, 저녁)로 먹은 음식을 이미지와 함께 간편히 기록합니다.
- **데이터 저장 전략 (DB-first):**
  - **모든 식사 기록은 처음 등록 시점부터 즉시 Supabase `meal_images` 테이블에 저장**됩니다. localStorage, sessionStorage 등 클라이언트 저장소는 일절 사용하지 않습니다.
  - 이미지 업로드 → AI 분석 → 메뉴명 입력 → 저장 전 과정이 모두 DB 기반으로 처리됩니다.
  - `source` 컬럼 값: 솔로 먹로그 등록 시 `'solo'`로 설정되어, 패밀리/맛톡 피드와 명확히 구분됩니다.
- **이미지 첨부 및 로컬 압축 (WebP 1024px 규격 통일):**
  - 사용자가 업로드하는 원본 이미지는 클라이언트 브라우저 단(Canvas API)에서 실시간으로 최대 1024px 해상도의 WebP 포맷(품질 75%)으로 압축 처리됩니다.
  - 이를 통해 원본 이미지 대비 약 98%의 용량을 획기적으로 절감(장당 평균 70KB 내외)하여 네트워크 대역폭 절약 및 고속 업로드가 가능하며, 백엔드/스토리지 저장 효율을 극대화합니다.
- **AI 메뉴명 추천 기능:**
  - 이미지 업로드 즉시 클라이언트 백엔드 비동기 통신(`/api/ai/analyze-food-image`)을 수행합니다.
  - OpenAI의 `gpt-4o-mini` API를 기반으로, 첨부된 음식 사진을 분석해 정확한 요리 이름을 식별한 뒤 메뉴명 입력란에 자동으로 채워 줍니다.
  - 분석 중일 때는 "AI가 사진을 분석하고 있어요..."라는 전용 로딩 인디케이터가 표출됩니다.
  - 사용자는 AI가 추천해 준 메뉴명을 자유롭게 수정하여 최종 등록할 수 있습니다.
- **식사 카드 구성 및 접기형 메모:**
  - 식사 사진과 식사 정보(유형 배지, 날짜, 별점, 메뉴명, 메모 등)가 함께 표시됩니다.
  - 레시피나 메모 정보는 내용이 길어질 경우를 대비해 **클릭 시 접고 펼칠 수 있는 아코디언(Collapsible) 구조**를 가집니다.
  - 식당 위치 정보로 외부 지도 링크가 연동된 경우 이를 명시하는 별도 표식이 지원됩니다.
- **초기 진입 샘플 노출 및 타입별 개별 소멸:**
  - 등록된 식사 일지 데이터가 전혀 없는 초기 진입 시 샘플 식사 일지(집밥, 배달, 외식 각 1개씩 총 3개)가 기본 노출됩니다.
  - 사용자가 특정 식생활 유형의 식사 기록을 등록하면 해당 유형의 샘플 카드만 골라서 소멸합니다. 배달과 외식도 각각 독립적으로 소멸합니다.
- **식사 카드 수정/삭제 UX 및 모달 타이틀:**
  - 식사 기록 등록 및 수정 모달 진입 시, 타이틀은 `(솔로) 먹로그 기록하기` 혹은 `(솔로) 먹로그 수정하기`로 표기되어 패밀리 모달과 시각적으로 구분됩니다.
  - 카드 우측 상단에 수정(연필) 아이콘만 단일 노출되며, 항상 흰색 반투명 둥근 배경으로 시인성을 보장합니다.
  - 삭제 액션은 수정 모달 내부의 [쓰레기통] 삭제 버튼으로 이관합니다.
  - 샘플 카드 삭제 시 "식사를 등록하면 샘플은 바로 사라집니다." 토스트 가이드를 표시하며 수정 모달은 유지됩니다.
- **사진 메타데이터(EXIF) 및 GPS 기반 외식 장소 자동 검색 (v2.4 추가):**
  - 외식(dineout) 식사 등록 시, 사용자가 식당 사진을 업로드하면 `exifr`를 통해 원본 사진의 EXIF 메타데이터에서 GPS(위도/경도)를 우선적으로 추출하여 해당 식당의 실제 위치를 검색합니다.
  - 사진에 GPS 정보가 없는 경우(메신저 다운로드 사진 등), 브라우저의 Geolocation API를 통해 사용자의 현재 위도/경도를 획득하는 폴백(Fallback) 로직이 동작합니다.
  - 획득한 위경도로 OpenStreetMap Nominatim reverse geocoding API를 통해 행정동(예: 청라동)을 분석한 후, 모바일 네이버 검색 결과를 실시간으로 파싱하여 실제 운영 중인 반경 내 맛집 목록(식당명, 업태 카테고리, 도로명 주소 및 대표 음식 썸네일 이미지)을 동적으로 로드 및 매핑합니다.
- **레시피 및 식당 외부 링크 미리보기 카드 세분화 (v2.3 추가):**
  - 식사 카드 우측 영역의 링크 박스 디자인을 세분화했습니다. Kakao/Google/Naver Map/Place 등의 지도 링크는 각 플랫폼별 색상 테마 및 고유 아이콘(`Map` / `Place`)으로 맞춤 표시됩니다.
  - YouTube, Instagram, TikTok 영상 링크 또한 각 플랫폼별 대표 컬러가 적용된 전용 카드 형태로 표시됩니다.
  - 그 외의 일반 외부 링크는 집밥의 경우 `"레시피 (Recipe / R)"`, 외식/배달의 경우 `"식당 링크 (Link / P)"`로 고도화 분류되어 렌더링됩니다.

#### ② 댓글 기능 (혼자 쓰는 메모형 댓글)
- **개요:** 솔로 먹로그의 각 식사 카드에 댓글을 달 수 있습니다. 솔로에서의 댓글은 본인만 보는 메모 형태이며, 나중에 가족방이나 맛톡에서 다른 사람들이 이어서 작성하는 구조로 연결됩니다.
- **저장:** 댓글은 Supabase `comments` 테이블에 저장됩니다. (localStorage 사용 없음)
- **댓글 UI 스펙 (패밀리와 완전 통일):**
  - 댓글 버블: `rounded-xl bg-orange-50/50 border border-orange-100 p-2.5`
  - 헤더: 작성자명(굵게) + 작성 시각(우측 정렬)
  - 액션 버튼: 하트(❤️) 좋아요 카운트 + `답글` 버튼 (패밀리와 동일 레이아웃)
  - 대댓글: 좌측 `border-l-2 border-orange-200` 들여쓰기
  - 입력창: `bg-gray-50 border-gray-200 rounded-lg` + 주황색 Send 아이콘 버튼

#### ③ 먹예약 (Reservation)
- **개요:** 지인, 가족 혹은 나만의 식사 약속 일정을 사전 기입하여 예약 현황을 한눈에 관리합니다.
- **데이터 저장 전략 (DB-first 전환):** 
  - 과거 localStorage 방식에서 벗어나, 이제 **모든 예약 정보는 Supabase `meal_reservations` 테이블에 실시간 동기화**됩니다. RLS 정책을 통해 본인만의 안전한 예약 관리가 보장됩니다.
- **초기 진입 샘플 날짜 동적 스케줄링**:
  - 사용자가 처음 진입 시 DB에 예약 내역이 없으면, **해당 유저의 가입일(최초 로그인 날짜)을 기준값으로 삼아, 가입일 다음 달 초/중순의 날짜로 예약 샘플 3개가 동적으로 생성**됩니다.
  - **주중(월~금) 조건**: 집밥(파스타) - 다음 달 5일 기준 가장 가까운 주중 / 배달(치킨) - 다음 달 12일 기준 가장 가까운 주중
  - **주말(토~일) 조건**: 외식(삼겹살) - 다음 달 10일 기준 가장 가까운 주말
- **샘플 데이터 소멸 정책 (유형별 분리)**:
  - 샘플 예약 정보(ID 1, 2, 3)는 수정 모달에서 저장을 시도할 시 차단됩니다.
  - 사용자가 실제 식사 예약을 등록할 때, **모든 샘플이 한 번에 사라지는 것이 아니라 등록한 식사 유형(집밥/배달/외식)에 대응하는 샘플 카드만 소멸**됩니다. 아직 데이터를 등록하지 않은 카테고리의 샘플은 화면에 계속 유지됩니다.
- **예약 상세 카드 및 스마트 액션 버튼**:
  - **외식 (Eating Out) & 집밥 (Homemade)**: 예약 등록 시 사용자가 기입해둔 지도/레시피의 원본 링크(`source_url`)를 보존하여, 예약 상세 모달 하단에 **[저장된 장소 링크 열기]** 또는 **[저장된 레시피 열기]** 버튼을 통해 즉시 해당 사이트로 연결해 줍니다.
  - **배달 (Delivery)**: 예약된 배달 식당명을 손쉽게 검색할 수 있도록 **[배달앱으로 검색]** 버튼을 클릭하면 배달의민족, 요기요, 쿠팡이츠 선택 메뉴가 펼쳐집니다. 앱을 선택하면 해당 서비스로 연결되며 동시에 **식당명이 클립보드에 자동으로 복사**됩니다.
- **URL 메타데이터 실시간 추출 및 정밀 파싱**:
  - 예약 추가 모달에서 링크를 붙여넣으면 **Microlink API**를 활용해 해당 링크의 실제 제목과 대표 썸네일 이미지를 실시간으로 가져와 자동 완성합니다.
  - **정규식(Regex) 정밀 필터링**: 제목 파싱 시 불필요한 유튜브 채널명, 대괄호/소괄호 구문 및 불필요한 어그로성 수식어(예: '초간단', '진짜 맛있는', '레시피', '방법'), 스마트 따옴표, 특수문자 등을 정규식으로 정밀 필터링하여 **"수육"**과 같이 핵심 메뉴명만 깔끔하게 정제하여 입력 창에 채워줍니다.

#### ④ 먹캘린더 (Meal Calendar)
- **개요:** 월간 달력 뷰를 기반으로 한 달간의 식사 이력을 시각적으로 일목요연하게 제공합니다.
- **기능 스펙:**
  - **초기 노출 화면(Default):** 캘린더 탭 진입 시 '먹예약' 뷰가 기본으로 노출되어 다가올 식사 일정을 즉각 확인할 수 있습니다.
  - 캘린더 상단 탭 순서는 [먹예약] - [먹로그] 순으로 배치됩니다.
  - 캘린더 날짜 클릭 시 해당 일자의 리스트 화면(먹로그/먹예약 탭)으로 바로 점프합니다.
  - 날짜 셀에는 썸네일 없이 메뉴명 텍스트 칩만 표시하며, 예약된 날짜는 별도 색상 배지로 구분됩니다.

### 2. 가족 식탁의 즐거움 (Family)
가족 구성원들이 함께 식사를 기록·공유하는 공동 공간입니다.
**솔로와 패밀리는 완전히 분리**되어 있으며, 솔로 먹로그의 내용은 패밀리에 자동으로 노출되지 않습니다.
가족 식사는 처음부터 패밀리 탭에서 직접 등록하는 방식을 원칙으로 합니다.

#### 탭 구조
패밀리 탭 상단에 `먹로그 / 먹예약 / 먹캘린더` 3개 서브탭이 제공됩니다.

---

#### ① 먹로그 — 공유된 가족 식사 피드
- **개요:** 가족방에서 직접 등록된 식사 카드만 표시합니다. 솔로에서 등록된 식사는 이 피드에 절대 표시되지 않습니다.
  - DB 쿼리 조건: `source = 'family-shared'` (솔로 `source: 'solo'` 및 기타 소스 일체 제외)
- **식사 카드 구성 (솔로와 동일):**
  - 식사 사진과 함께 식사 유형, 메뉴명, 등록자, 등록 시각, 별점 평균이 표시됩니다.
  - 외부 지도 링크가 있을 경우 이를 직관적으로 알 수 있는 연동 표식이 표시됩니다.
  - 댓글 토글 버튼을 통해 댓글 목록을 접고 펼칠 수 있습니다.
- **식사 직접 등록 및 모달 타이틀:**
  - 우측 하단의 (+) 버튼을 활용해 가족 먹로그에 식사를 즉시 기록하여 공유할 수 있습니다.
  - 솔로 탭의 `AddLogModal` 입력을 공용으로 제공하며, 등록 즉시 `source = 'family-shared'` 데이터로 반영되어 실시간으로 공유됩니다.
  - 등록 및 수정 모달 진입 시 타이틀은 `(패밀리) 먹로그 기록하기` 혹은 `(패밀리) 먹로그 수정하기`로 노출되어 솔로 모달과 명확하게 구분됩니다.
- **별점 시스템:**
  - 각 식사는 마감 기한 없이 언제든 별점 평가가 가능합니다.
  - 평가 기간 중(isOpen=true): 카드 클릭 시 별점 입력 모달이 열립니다. 가족 구성원 1인당 1회 평가 가능.
  - 별점은 언제든 추가/수정 가능하며, 가족 중 1명이라도 5점을 부여하면 맛톡에 즉시 게시됩니다.
  - 평균 별점은 카드 우측 하단에 상시 표시됩니다.
- **5점 최초 평가 시 맛톡 승격 동의 모달 연동 (v2.7 추가):**
  - 가족 식사에 최초로 5점을 부여할 때, 솔로 탭과 동일하게 맛톡 공개 동의 및 자동 처리 선택창(Modal)을 거칩니다.
  - "이후 항상 이 선택 적용" 체크 시 `localStorage`에 승낙 상태가 기록되며 다음 5점 평가부터는 팝업 없이 즉시 맛톡 피드에 등록됩니다.
  - 맛톡 피드 등록 시, 로컬의 팝업 모달을 즉시 닫고 1.5초(성공 토스트 감상 시간) 뒤에 자동으로 맛톡 피드 탭으로 화면을 부드럽게 전환(Redirect)합니다.
- **5점 ➔ 4점 이하 다운그레이드 시 맛톡 자동 수거 및 차단 (v2.7 추가):**
  - 가족 식사에 매겨진 5점 평가를 4점 이하로 낮출 때, 나 혹은 다른 가족 구성원 통틀어 더 이상 5점 평가가 남지 않게 되는 경우:
    - 맛톡 피드에 등록된 해당 식사에 다른 유저의 댓글/좋아요 활동이 발생했다면 평점 낮추기(다운그레이드)가 원천 차단되며 경고 토스트가 발생합니다.
    - 다른 유저의 활동이 없는 빈 식사인 경우, 맛톡 피드에서 해당 식사 기록을 즉시 수거(status -> 'pending'으로 롤백) 처리합니다.
- **초기 진입 샘플 노출:** 공유된 가족 식사 데이터가 없을 경우 가상의 샘플 식사 카드와 가이드용 댓글이 노출됩니다. 실 데이터 등록 시 전환됩니다.

#### ② 먹예약 — 위시리스트 + 예약 목록 서브탭 (v2.6 전면 개편)
- **개요:** 가족 식사 예약을 위시리스트와 예약 목록 두 단계로 분리하여 관리합니다. 기존의 투표 기능과 알림설정 UI는 MVP 과잉으로 판단하여 제거되었습니다.

- **셰프 정보 바:**
  - 먹예약 탭 상단에 현재 담당 셰프 정보가 항상 표시됩니다.
  - 셰프가 지정되어 있으면 해당 멤버명, 미지정 시 "방장이 임시 셰프"로 표시됩니다.
  - 셰프 본인에게만 `+` 버튼이 노출되어 위시리스트/예약을 직접 추가할 수 있습니다.

- **서브탭 구조:**
  - `📋 위시리스트` | `📅 예약 목록` 두 개 서브탭으로 구성됩니다.
  - 집밥 / 배달 / 외식 / 전체 필터 칩이 서브탭 하단에 가로 스크롤로 제공됩니다.

- **📋 위시리스트 (가족 공용):**
  - 가족 구성원 누구든지 날짜 없이 먹고싶은 메뉴·식당을 자유롭게 추가할 수 있습니다.
  - DB 저장: `meal_reservations` 테이블, `source = 'family_wishlist'`, `date = null`
  - **좋아요:** 각 위시리스트 카드에 ❤️ 좋아요를 누를 수 있으며, `meal_likes` 테이블에 저장됩니다.
  - **댓글:** 위시리스트 카드에도 댓글/답글을 달 수 있으며, 셰프가 이를 참고하여 날짜를 확정할 수 있습니다.
  - **날짜 잡기 (셰프 전용):** 셰프 계정에게만 각 위시리스트 카드에 `📅 날짜 잡기` 버튼이 노출됩니다. 클릭 시 날짜 선택 모달(`AddReservationModal`)이 열리며, 동일한 레코드 ID를 유지한 채 `source = 'family'`로 전환되어 예약 목록 탭으로 자동 이동합니다.

- **📅 예약 목록:**
  - 셰프가 날짜를 확정한 `source = 'family'` 레코드만 표시됩니다.
  - 날짜 정보(📅 날짜, 시간)가 카드에 표시됩니다.
  - 셰프 또는 해당 예약 작성자만 삭제할 수 있습니다.
  - 셰프에게는 `예약 추가` 버튼이 별도 노출되어 위시리스트를 거치지 않고 직접 예약을 생성할 수도 있습니다.

- **동적 샘플 배치 및 유형별 소멸 시스템:**
  - 왓잇 서비스 공통 UI/UX 원칙에 맞춰, 위시리스트 및 예약 목록에 데이터가 비어있을 시 빈 화면 대신 집밥/배달/외식 3종의 샘플 카드를 기본 노출합니다.
  - 샘플 카드의 우상단에는 `💡 SAMPLE` 노란 대각선 리본 배지가 표시됩니다.
  - 사용자가 특정 식생활 유형(집밥/배달/외식)의 데이터를 등록하면 해당 유형의 샘플만 소멸하고, 미등록 유형의 샘플은 유지됩니다.

- **반응형 2열 분치 및 컨트롤 구성:**
  - **데스크톱 (PC/태블릿)**: 좌측 `📋 가족 위시리스트` / 우측 `📅 확정 예약 목록` 2열(Split View)로 동시 표출되어, 셰프가 식구들의 위시리스트 후보와 확정된 예약 일정을 한눈에 비교 관리할 수 있습니다.
  - **모바일**: `[📋 위시리스트]` ↔ `[📅 예약 목록]` 탭 스위처를 통해 한정된 화면을 효율적으로 전환 사용합니다.
  - 상단에 솔로 먹예약과 동일한 `검색창 + 정렬 드롭다운` 및 수량 배지가 포함된 `카테고리 칩 (전체 / 집밥 / 배달 / 외식)`이 깔끔하게 통합 배치됩니다.

- **공간 최적화 2단 카드 레이아웃 (v2.6 개선):**
  - **상단 프로필 헤더**: 업로드한 가족 멤버의 아바타, 닉네임, 업로드 상대 시각(`createdAt`, 예: 방금 전, 2시간 전) 및 식사 유형 배지가 시각적으로 표시됩니다.
  - **공간 최적화 2단 분치**: 카드 내부를 좌/우 2단으로 분할하여, **좌측 영역**에는 `메뉴명`, `위치/위시날짜`, `말풍선 메모`를 컴팩트하게 배치하고, **우측 영역**에는 `URL 썸네일 이미지`(`size-24`~`size-28`)를 깔끔하게 유지합니다.
  - **직관적 썸네일 & 링크 연결**: 우측 썸네일 사진 클릭 시 원본 URL 링크로 바로 이동(공통 컨벤션)하며, 외부 링크 아이콘 오버레이가 제공됩니다.
  - **하단 액션 바**: 맛톡과 동일한 `❤️ 좋아요` 카운터 및 `💬 댓글` 버튼이 제공되며, **`📅 날짜 잡기` 버튼은 오직 셰프(Chef)에게만 노출**됩니다.
  - **수정 및 삭제 모달 연동**: 카드 우상단 연필 아이콘 클릭 시 수정 모달이 열리며, 모달 내부에서 수정 및 삭제가 안전하게 수행됩니다.

#### ⑤ 우리가족 셰프 지정 및 먹예약 결정 권한 (v2.6 개편)
- **개요:** 가족 식사 예약의 최종 결정권을 가지는 셰프를 지정합니다.
- **초기 자동 폴백:**
  - 가족 그룹 생성 직후 또는 셰프가 미지정 상태일 경우, **방장(Owner)이 자동으로 임시 셰프 역할을 수행**합니다.
- **셰프 지정 및 변경:**
  - 방장은 구성원 중 1명을 셰프로 선정할 수 있으며, 셰프 프로필에 🍳 ChefHat 배지가 표시됩니다.
  - 셰프 변경 시 선택된 멤버의 userId가 `family_groups.chef_id` 칼럼에 저장되어 영구 동기화됩니다. (브라우저 새로고침 후에도 유지)
  - **방장 전용 관리 권한 (보안 강화)**: 가족 대표 사진 변경 및 셰프 지정 권한은 오직 **가족 방장(`isFamilyOwner`)**에게만 부여되며, 백엔드 API(`/api/db/write`)에서도 본인 소유의 가족 그룹(`owner_id === userId`)만 변경할 수 있도록 엄격히 제한됩니다. 일반 구성원은 방장이 설정한 대표 사진과 셰프 프로필을 읽기 전용으로 동기화 받아 조회합니다.
  - 셰프 변경 권한은 방장(`isFamilyOwner`)에게만 부여됩니다.
- **셰프 권한 (먹예약 중심):**
  - 위시리스트 카드에서 `📅 날짜 잡기` 버튼 표시 및 예약 확정 처리
  - 예약 목록에서 직접 예약 추가 가능
  - 타인 등록 예약도 삭제 가능

#### ⑥ 동적 가족 구성원 관리 (가상 플레이스홀더 완전 제거)
- **기능 스펙:**
  - 기존의 하드코딩된 가상 가족 플레이스홀더(엄마, 아빠, 동생)를 완전히 제거했습니다.
  - 비로그인(게스트) 상태나 초대한 동료가 없는 초기 상태에서는 오직 "나"와 `+ 초대` 버튼만 깔끔하게 노출됩니다.
  - 초대를 통해 실제 가입된 사용자만 동적으로 목록에 추가 및 표시되어 실제 가족 그룹 데이터의 순수성을 보장합니다.

#### ⑦ 비로그인(게스트) 접근 제한 및 가족 사진 동기화
- **기능 스펙:**
  - 비로그인 게스트 상태에서는 특정 사용자의 가족명 대신 **"게스트 가족"** (구성원: "1명의 구성원")으로 깔끔하고 직관적으로 표출됩니다.
  - 로그인 완료 시 사용자의 닉네임에 맞춰 `OOO 가족` 또는 초대한 방장의 가족명(`familyHostName` 리액트 상태 동기화)으로 에러 없이 즉시 동적 전환됩니다.
  - **가족 대표 사진 실시간 폴백 및 메뉴 전환 동기화**: 방장이 등록한 가족 사진은 DB 최신 레코드 폴백 쿼리를 통해 타 멤버 계정(예: 멀린)에서도 100% 동기화되어 표시됩니다. 또한 메뉴 탭 이동(`먹로그` ↔ `먹예약` ↔ `먹캘린더`) 및 브라우저 창 포커스 시 자동으로 데이터가 갱신되어 새로고침 없이도 즉시 업데이트된 사진이 표출됩니다.
  - 비로그인 게스트는 공유된 식사, 오늘의 메뉴 현황, 예약 목록 등을 자유롭게 조회할 수 있으나, 위시리스트 추가, 예약 변경, 사진 업로드, 셰프 지정 등 작성/변경 동작 시 즉시 로그인 모달로 안내합니다.

#### ⑧ 가족 초대 및 합류 확인 모달 (Join Family Flow)
- **기능 스펙:**
  - 피초대자가 가족 초대 URL을 통해 서비스에 진입하고 가입/로그인을 완료하면, 가족 합류 확인 모달이 자동으로 표출됩니다.
  - 피초대자가 합류를 '수락'하면 대기 상태가 되며, 패밀리 방의 방장이 승인 처리를 완료하여 상태가 `REWARDED`로 업데이트되어야만 정식 가족으로 구성원 목록에 노출됩니다.

#### ⑨ 모임 및 하이브리드 헤더 (Group) (v2.7 추가)
가족(유일함)과 별개로, 마음이 맞는 사람들(지인, 직장동료 등)끼리 모여 식사 기록 및 일정을 공유할 수 있는 다중 모임방 기능입니다.
* **모임 가로 스크롤 및 무제한 추가**:
  * 한 사용자가 가입하거나 생성할 수 있는 모임의 개수 제한은 없으며, 개수가 많아질 경우 가로 스크롤을 통해 좌우로 부드럽게 탐색할 수 있습니다.
* **모임 선택 및 토글 백**:
  * 이미 선택되어 활성화된 모임을 한 번 더 클릭하면 모임이 비활성화되며, 자동으로 기본 가족(Family) 모드로 원상복귀합니다.
* **가족/모임 하이브리드 헤더 UI**:
  * 상단 헤더 영역을 좌/우 2개의 섹터로 분리하여 **좌측: 가족 카드**, **우측: 모임 목록 및 모임 추가 `(+)` 버튼**을 배치했습니다.
  * **PC 아코디언 인터랙션**: 두 영역이 공존하다가 클릭한 활성화 영역은 확장(`65%` 또는 `35%`)되고, 반대편 영역은 타이틀만 남고 슬라이딩 축소됩니다.
  * **모바일**: 활성화된 탭 하나만 단일 풀스크린 노출되며, 비활성화된 영역은 완전히 숨김 처리됩니다.
* **모임 방장(Owner) 권한**:
  * 카카오톡처럼 모임을 생성한 사람이 방장이 되며, 방장만 모임을 삭제(해체)하거나 멤버를 추방할 수 있습니다.
  * 일반 모임원은 초대 링크를 복사하여 공유하거나 스스로 모임을 탈퇴할 수 있습니다.
* **외식 전용 (Dineout-only) 심플화**:
  * 모임은 '외식(dining)'만 하는 것으로 전제하여 집밥/배달 옵션을 전부 제거했습니다.
  * 모임 탭 활성화 시 식사 로그 및 예약 추가 모달에서 식사 유형 선택 바가 비활성화되고, 기본 식사 유형이 "외식"으로 고정됩니다.
  * 위시리스트 및 예약 목록의 샘플 식사도 오직 외식 샘플만 남고 집밥/배달 샘플은 제외됩니다.
* **초대 링크 및 실적 로직 연동**:
  * 모임방 상세 메뉴에서 [초대 +] 클릭 시 복사되는 초대 링크에는 모임 ID와 함께 초대자의 추천인 코드(`ref=추천코드`)가 동적으로 결합됩니다:
    * `https://[도메인]/whateat?ref=[추천코드]&group=[모임ID]`
  * 피초대자가 해당 링크를 클릭해 가입 및 로그인을 완료하면 모임 합류 확인 팝업 모달이 표출되며, 가입 시 추천인 실적으로 자동 합산됩니다.

### 3. 동네 찐 맛집 발견 (Talk)
사용자가 등록한 실주소/학교 지역 기반으로 신뢰도 높은 이웃들이 직접 작성한 진짜 맛집 정보들만 엄선해 보여주는 필터링 정보 공간입니다.

#### ① 광고 없는 이웃 리뷰
- **개요:** 대행사 광고나 바이럴 포스팅이 전혀 없는, 같은 행정구역 및 학교 인근의 주민들이 순수하게 작성한 리뷰만 보여줍니다.
- **정렬 및 검색:** 5점 만점 평점 평균순, 최다 리뷰 등록순 등으로 동네 찐 맛집 순위를 다이나믹하게 필터링하여 사용자에게 맞춤 추천합니다.
- **실시간 맛톡 연동 및 등록 일시:**
  - 솔로/패밀리 식사 일지에서 **누구라도 5점을 부여하고 공개를 승낙하는 즉시** 해당 게시글이 맛톡 피드에 노출(`status: 'approved'`)됩니다.
  - 피드에 노출되는 최초 작성자(author)는 솔로 식사일 경우 이미지 업로더의 닉네임과 프로필로 설정되지만, **패밀리 식사일 경우 해당 식사를 공유한 가족의 이름(예: `[방장닉네임] 가족`)**으로 자동 갱신 및 결합하여 맛톡에 표시됩니다. (가족 방장의 닉네임은 `referrals` 추천 관계 테이블을 추적하여 동적으로 획득합니다.)
  - 맛톡 피드에 표시되는 등록 일시는 식사가 최초 작성된 시각이 아니라, **맛톡에 최종 승격되어 연동된 시점의 일시**로 표기됩니다.
- **맛톡 중복 승격 방지 및 실시간 별점 누적:**
  - 가족 및 모임 식사의 경우, 한 구성원에 의해 이미 맛톡으로 승격(`status: 'approved'`)되었다면 **다른 구성원이 추가로 별점을 매기더라도 맛톡 피드에 게시글이 중복 생성되지 않고** 단일 게시물로 유지됩니다.
  - 이후에 등록되는 평가는 누적되어 실시간 평점 평균(Rating Average) 및 평가 참여자 수에 정상 합산되어 반영됩니다.
  - **별점 세부 정보 표시:** 맛톡 피드에 노출되는 식사는 최초 등재 유형(소스: 솔로, 가족, 모임)과 평점 평균 및 평가 참여자 수를 한눈에 볼 수 있도록 정보를 구분하여 표시합니다.
    - 예시: `5.0 (1명) 솔로`, `4.0 (3명) 가족`, `4.2 (7명) 모임`
    - 식당명 표기 시 외부 지도 링크가 있을 경우 앞단에 직관적인 연동 아이콘 표식이 노출됩니다.
  - **가족 식사 평점 실시간 누적 집계 개선 (v2.7 추가):**
    - 가족 식사는 `meal_id` 컬럼이 `null`로 저장되므로, 기존의 `meal_id` 기반 집계에서 벗어나 `meal_images`의 기본 키(UUID인 `id`)를 기준으로 평점 데이터를 동적으로 맵핑하고 누적 평균 점수를 가져오도록 수정하여 평점 누락 현상을 완전히 해결했습니다.
  - 1인당 한 식사에 대해 별점을 매기는 행위는 단 1회로 제한됩니다.

#### ② 맛톡 카드 액션 (좋아요 / 댓글 / 담기)
- **좋아요 (실시간 동기화 및 RLS 강화):** 
  - 이웃이 등록된 맛집 피드 글에 대해 공감 반응을 보낼 수 있습니다.
  - **Supabase Realtime 연동 (Broadcast)**: 기존의 PostgreSQL 논리 복제 슬롯(`postgres_changes`)의 테이블 설정 갱신 지연 현상을 회피하기 위해, 클라이언트 간 초고속 **Broadcast** 채널 이벤트(`LIKE`, `UNLIKE`)를 쏘고받아 즉각적으로 화면의 좋아요 숫자를 동기화합니다.
  - **보안 삭제(secureWrite) 적용**: 클라이언트 직접 삭제 권한 차단(RLS 강화)에 따라, 좋아요 취소 시 서버 사이드 API(`/api/db/write`)를 경유하도록 이관했습니다.
  - **이중 카운팅 방지**: 본인의 좋아요/취소 액션은 화면에 즉시(Optimistic UI) 반영되므로, 실시간 소켓으로 수신된 본인 유래 이벤트에 대해서는 카운트 중복 처리를 차단하는 필터링이 구현되어 있습니다.
  - **로그인 연동 자동 갱신**: 최초 접속 시 세션 로딩 대기로 인해 좋아요 소유권이 누락되지 않도록, Hub 로그인 완료 시점(`isLoggedIn`, `user?.id`)을 감지하여 피드 정보를 재조회하고 붉은 하트 상태를 동적으로 갱신합니다.
- **댓글:** 맛톡 피드 글 하단에 댓글 및 답글(대댓글)을 작성하여 소통할 수 있으며, 이 또한 Supabase Realtime 채널을 통해 이웃의 댓글 작성 상태가 실시간 동기화됩니다.
- **담기 및 먹예약 자동 연동:** 
  - 맛톡 피드의 식사 기록을 자신의 개인(솔로) 또는 가족 공간으로 수집하는 기능입니다.
  - 맛톡 카드에서 `담기`를 실행하여 **`👤 솔로 먹예약`** 또는 **`👨‍👩‍👧 가족 먹예약`** 중 하나를 선택합니다.
  - 선택 즉시 해당 탭(솔로 또는 가족)의 **먹예약 탭으로 화면이 즉시 전환**되고, 예약 등록 모달이 자동으로 활성화됩니다.
  - 활성화된 예약 모달에는 가져오고자 한 맛톡 카드의 **메뉴명, 식사 유형(집밥/배달/외식), 식당명(외식/배달의 경우)**이 **자동 완성(Pre-filled)** 상태로 설정되며, 사용자는 상세 일시(날짜, 시간)만 기입하여 손쉽게 예약 처리를 끝낼 수 있습니다.
  - 맛톡 카드를 담아갈 때, 해당 게시물에 **자동으로 '좋아요'가 눌리도록 강제 처리**합니다 (중복 클릭 방지 처리가 적용되어 이미 좋아요 상태라면 카운트가 이중 증가하지 않습니다).

#### ③ 맛톡 연동 및 자동 처리 안내 UX (v2.3 추가)
- **공개 동의 모달**: 5점 별점을 최초로 부여하여 맛톡에 등록할 때, "맛톡 공개 동의" 모달창이 활성화되어 공개 허용 여부를 수집합니다.
- **자동 공유 시 안내 토스트 제공**: 모달창에서 '이후 항상 이 선택 적용(자동 처리)'을 선택하여 승낙(approved)해 둔 경우, 다음부터는 공개 동의 모달이 팝업되는 대신 `"5점 별점 식사가 맛톡 동네 피드에 자동 공유되었습니다!"` ✨ 안내 토스트 메시지가 노출되고, 1.5초간의 시각적 대기 시간을 준 뒤 맛톡 동네 피드로 부드럽게 화면을 전환시킵니다.
- **방어 로직 (v2.5 추가)**: 솔로 탭 등에서 메모(레시피/팁)가 기재되지 않은 식사 기록이라 하더라도, 공유 과정 중 런타임 크래시가 발생하지 않도록 빈 배열 필터링에 대한 안전장치(Safe Optional Chaining)가 완비되어 있습니다.

#### ④ 맛톡 공유 기록 회수 및 차단 정책 (v2.3 추가)
- **이웃 활동 미발생 시 자동 수거**: 맛톡 피드에 공유된 5점 식사 기록에 대해 타인의 활동(댓글 등)이 전혀 발생하지 않은 상태에서 작성자가 별점을 4점 이하로 낮추거나 기록을 수정하면, `"다른 유저의 활동이 없어 맛톡 피드에서 식사 기록을 수거했습니다."` 🧹 토스트와 함께 해당 식사는 맛톡 피드에서 즉각 내려갑니다 (status가 'pending'으로 안전하게 강등 조정됩니다).
- **이웃 활동 발생 시 수정 원천 차단**: 다른 이웃의 댓글, 좋아요 등 실제 유저 활동이 이미 발생한 식사 글인 경우, 작성자가 해당 식사 기록을 수정하는 행위를 원천 차단합니다. 수정 버튼(연필 아이콘) 클릭 시 `"맛톡 이웃의 활동(댓글/좋아요)이 있어 수정할 수 없습니다."` 🔒 경고 토스트를 노출하며 수정 모달 자체가 열리지 않도록 보호합니다. 이는 평점을 낮춰서 수거하는 행위뿐만 아니라, 기존 기록 내용(메뉴명, 주소, 이미지 등)을 변경하여 정보의 일관성을 해치는 것을 방지하기 위함입니다.

### 4. 우리 아이 학교 급식 (School)
초·중·고등학생 자녀를 둔 학부모와 학생들이 매일의 학교 급식 메뉴를 체크하고 평점을 남기며 학습형 미니게임을 즐기는 공간입니다.

#### ① 급식 메뉴 확인 & 평가
- **개요:** 교육행정정보시스템(NEIS) API를 연동하여 등록된 학교의 당일 식단 정보(메뉴 목록, 칼로리, 알레르기 유발 정보, 원산지 정보)를 정확하게 노출합니다.
- **기능 스펙:** 
  - 학교를 등록하지 않았거나 등록된 학교의 당일 급식 데이터가 부재한 경우, 기본 플레이스홀더 성격의 가상 샘플 급식 정보가 예쁘게 구성되어 나타납니다.
  - 사용자가 급식에 대해 직접 평점을 매기거나 댓글을 작성하여 남들과 소통할 수 있는 직관적인 피드백 구조를 제공합니다.

#### ② 식단 연계 AI 퀴즈
- **개요:** 당일 급식 식단 재료와 영양성분을 연동하여 생성된 미니 영양 퀴즈를 풀어보는 재미있는 상식 퀴즈 게임입니다.
- **기능 스펙:** 
  - 실제 당일 급식 식재료 정보에 입각하여 AI 영양 퀴즈가 실시간 생성됩니다.
  - 퀴즈 정답 제출 시 상세하고 친절한 AI 영양 상식 해설 피드백이 제공됩니다.
  - 정답 획득에 성공할 때마다 개인 퀴즈 이력이 누적되어, 명예의 전당에 챔피언 자격으로 이름을 올릴 수 있는 성취 요소를 포함합니다.

### 5. 프로필 및 앱 초대 (Profile)
통합 허브 계정 정보 조회, 초대 실적 리스트, 그리고 전반적인 계정 알림 및 동기화 설정을 수행하는 단독 공간입니다.

#### ① 앱 초대 실적 관리 (앱 초대 List)
- **개요:** 내 추천 코드를 타고 서비스에 진입해 회원가입을 거쳐 정식 이벤트를 완수한 친구들의 누적 가입 실적을 관리합니다.
- **기능 스펙:**
  - 코인이 존재하지 않는 왓잇 서비스 스펙에 맞춰, 보상 획득을 뜻하는 기존 `지급 완료` 뱃지 대신 **`초대 성공`** 뱃지를 달아 코인 용어를 완전히 순화했습니다.
  - 초대 링크를 타고 회원 가입을 시작하였으나 아직 정식 회원 조건(가족 수락 등)을 채우지 않은 대기 중인 유저의 진행 현황도 초대자가 파악할 수 있도록 **`대기 중 (조건 미달성)`** 배지를 실적 리스트에 정상 복구하여 표시해 줍니다.

#### ② 헤더 탭 하이라이트 배제 및 해시 갱신 네비게이션
- **기능 스펙:**
  - 프로필 설정 페이지(`/profile`) 진입 시 헤더의 4대 탭(솔로, 패밀리, 맛톡, 급식) 중 어느 것도 활성화되지 않도록 `activeNavTab` 프로프 값을 `null`로 강제 매핑합니다.
  - 프로필 헤더에서 다른 탭 클릭 시 로컬스토리지를 거치지 않고 Next.js 라우터 해시(`/#[탭명]`)로 즉각 이동합니다.
  - 메인 컴포넌트(`WhatEatApp`)의 `hashchange` 이벤트 리스너를 결합하여, 프로필을 이탈해 복귀하는 첫 번째 터치만으로 딜레이 없이 해당하는 메인 탭으로 원활하게 전환되도록 네비게이션 경험을 강화했습니다.

## 🗄️ 데이터 저장 전략

### 전체 원칙: DB-first (localStorage 사용 금지)
- **모든 사용자 데이터는 처음 등록 시점부터 즉시 Supabase DB에 저장**합니다.
- localStorage, sessionStorage 등 클라이언트 저장소는 세션 내 일시적 UI 상태(온보딩 닫기 여부 등) 용도로만 제한적으로 사용하며, 실제 식사 데이터·댓글·별점은 일절 클라이언트에 저장하지 않습니다.
- **클라이언트 직접 쓰기 차단 (RLS 준수)**: 클라이언트에서 Supabase JS SDK를 통해 직접 DB에 쓰거나(insert/update/delete) 스토리지를 조작하는 것을 금지하며, 모든 쓰기/업로드 작업은 인증 필터링이 적용된 안전한 백엔드 API 라우트를 통해 대행합니다.

### 데이터베이스/스토리지 보안 API 개요
* **DB 보안 쓰기 API (`/api/db/write`)**: 
  * 프론트엔드의 `secureWrite` 헬퍼를 통해 호출되며, 요청 헤더의 Merlin Hub JWT 토큰을 검증해 사용자 식별자를 획득합니다.
  * `uploaded_by`, `user_id` 등 소유자 검증을 거쳐 본인의 레코드만 생성/수정/삭제하도록 안전하게 처리한 뒤 `supabaseAdmin` 권한으로 실행합니다. (단, `meal_images` 테이블의 업데이트에 대해서는 타 가족 구성원이 올린 식사를 다른 멤버가 5점을 주어 승격/강등 시킬 수 있도록 본인 소유권 검증 조건을 완전히 제거하여 유연한 비즈니스 로직 제어를 지원합니다.)
* **스토리지 보안 업로드 API (`/api/db/upload-image`)**:
  * Merlin Hub 토큰 검증을 통과한 사용자만 base64 형식의 이미지 파일과 파일명을 전송하여 호출합니다.
  * 서버에서 base64를 디코딩하여 스토리지의 `meal-images` 버킷에 `supabaseAdmin`으로 업로드하고 공개 URL을 반환합니다.

### 주요 테이블 및 source 구분
| 테이블 | 용도 | source 값 |
|---|---|---|
| `meal_images` | 식사 이미지 기록 | `'solo'` (솔로) / `'family-shared'` (패밀리) |
| `comments` | 댓글 (솔로·패밀리·맛톡·예약 공용) | meal_id 기반 참조 |
| `meal_ratings` | 별점 (가족 구성원별 1회) | meal_image_id 기반 참조 |
| `meal_menus` | 셰프가 결정한 오늘의 메뉴 | `school_code='family'` |
| `meal_reservations` | 솔로/가족 먹예약 및 위시리스트 | `'solo'` / `'family'` / `'family_wishlist'` |
| `meal_likes` | 위시리스트·먹로그 좋아요 | meal_id 기반 참조 |
| `family_groups` | 가족 그룹 정보 (사진, 셰프 ID) | `owner_id`, `chef_id`, `family_photo` |

### 이미지 업로드 파이프라인
* **솔로 및 패밀리 식로그 이미지**:
  1. 클라이언트 Canvas API로 WebP 1024px 75% 품질 압축 (업로드 전)
  2. `/api/db/upload-image` → Supabase Storage 저장 및 공개 URL 반환 (서버 대행)
  3. `/api/db/write` (action: 'insert') → `meal_images` 테이블에 메타데이터 기록 (서버 대행)
* **급식 이미지 (학교 배틀 모드)**:
  1. 클라이언트 Canvas API로 WebP 1024px 75% 품질 압축 (업로드 전)
  2. `/api/meal-images/upload` → Supabase Storage 저장
  3. `/api/meal-images/create` → `meal_images` 테이블에 메타데이터 기록
  4. `/api/ai/analyze-food-image` → 비동기 AI 메뉴명 분석 (gpt-4o-mini)
  5. 맛톡 승격 조건: 5점 부여 + 공개 동의 → `status: 'approved'` 업데이트

### 데이터베이스 보안 및 예외 진단 정책 (v2.2 추가)
- **보안 설정 및 확장 기능 최적화**:
  - 프로젝트에서 사용하지 않는 `pg_graphql` 확장 기능을 비활성화하여 외부 스키마 및 테이블 구조 노출 위험을 원천 차단했습니다.
  - `SECURITY DEFINER` 함수(`get_menu_item_rating_stats`, `update_menu_item_rating_stats`, `update_school_rating_stats`)의 외부 `EXECUTE` 권한을 회수(REVOKE)하고, 오직 DB 내부 트리거 및 `postgres`, `service_role` 권한으로만 실행을 허용하여 클라이언트 단의 무분별한 RPC 실행을 봉쇄했습니다.
- **실시간 예외 진단 구조 고도화**:
  - 프론트엔드(`MealLogTab`, `FamilyPage` 등)에서 데이터베이스 저장 및 이미지 업로드 예외 발생 시, 하드코딩된 에러 메시지 대신 **실제 서버 응답 및 네트워크 예외 문구를 토스트 알림에 노출**하도록 개선했습니다. 이를 통해 세션 만료, 권한 오류, 배포 서버 환경변수 누락 등의 문제를 운영 중에 실시간으로 진단 가능하도록 보완했습니다.

#### ③ 패밀리 먹예약 탭 — 추가 고도화 항목 (v2.6 기준 미구현)
- 위시리스트 카드에서 날짜 잡기 시 기존 데이터 자동 프리필(메뉴명·장소·URL 등)
- 예약 목록 날짜 기준 정렬 및 달력 뷰 연동
- 모임방(Group) 먹예약: 셰프 개념 대신 방장이 결정권을 가지며 권한 이전 기능 제공 (향후 구현)

#### ④ 맛톡 피드 — 반응 없는 게시물 자동 소멸 정책 (콘텐츠 품질 유지)
- **배경 및 목적:** 맛톡 피드에 등록된 5점 만점 게시물 중, 장기간 좋아요 등의 피드백 반응이 없는 저품질/비인기 게시물을 자동으로 소멸시켜 동네 찐 맛집 피드의 콘텐츠 신선도와 품질을 유지합니다.
- **소멸 기준:**
  - 5점 획득으로 맛톡에 승격된 카드가 노출된 이후, **일정 기간(예: 30일/90일) 동안 좋아요 반응이 기준치 미만(예: 0개 또는 1개 미만)**인 게시물은 맛톡 피드(`status: 'approved'`)에서 자동 소멸(`status: 'expired'`) 처리합니다.
  - 소멸 처리 시, 원작성자의 개인 솔로/가족 먹로그 내에 저장된 원본 데이터에는 아무런 영향을 주지 않고 안전하게 보존됩니다.
- **초기 유예 기간 적용 (유저 모집용):**
  - **서비스 론칭 초반에는 유저 수가 부족하므로 자동 소멸 기능을 비활성화** 상태로 시작합니다.
  - 인원이 충족되는 시점(예: 출시 후 약 반년/6개월 내외)까지는 그대로 노출을 유지하고, 활성화 타겟 시점에 환경변수(`TALK_AUTO_EXPIRE_ENABLED`)를 통해 기능을 즉시 활성화합니다.

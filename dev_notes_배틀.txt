# 메뉴 배틀 시스템 알고리즘 정리

## 📅 2025-07-31 추가: 배틀 페이지 날짜 동기화 기능 개선

### 💡 문제 상황
- 일별/월별 뷰 모드 전환 시 `selectedDate`와 `selectedMonth` 파라미터가 비동기적으로 처리되어 데이터 로딩 불일치 발생
- 특히 특정 날짜로 일별 조회 후 월별로 전환했다가 다시 일별로 돌아오면 월1의 1일로 초기화되는 문제

### 👷 수정 로직
1. **마지막 선택 날짜 저장 기능 추가**
   ```typescript
   // 이전 일별 보기에서 사용했던 날짜를 저장하는 상태
   const [lastSelectedDate, setLastSelectedDate] = useState(getCurrentDate());
   ```

2. **일별 → 월별 전환 시 현재 날짜 기억**
   ```typescript
   // 일별에서 월별로 전환 시 현재 날짜 저장
   setLastSelectedDate(selectedDate);
   const month = selectedDate.substring(0, 7);
   setSelectedMonth(month);
   ```

3. **월별 → 일별 전환 시 이전 날짜 복원**
   ```typescript
   // 이전 날짜가 현재 선택된 월에 속하는지 확인
   const lastMonth = lastSelectedDate.substring(0, 7);
   if (lastMonth === selectedMonth) {
     // 동일한 월이면 이전 날짜 사용
     setSelectedDate(lastSelectedDate);
   } else {
     // 다른 월이면 현재 선택된 월의 1일로 설정
     setSelectedDate(`${selectedMonth}-01`);
   }
   ```

### 💯 개선 결과
- 일별 뷰에서 특정 날짜(7월 15일)를 보던 중 월별 뷰로 전환했다가 다시 일별로 돌아오면 월이 변경되지 않는 한 이전에 보던 날짜(7월 15일)가 유지됨
- 문제 해결 방식: 현재 보는 날짜 상태를 기억하는 로직 추가 완료

## 🗄️ 데이터베이스 테이블 구조

### 1. meal_menu_items (메뉴 아이템)
- id: 메뉴 아이템 ID
- item_name: 메뉴명 (예: "김치찌개")
- meal_id: 급식 ID (외래키)

### 2. meal_menus (급식 정보)
- id: 급식 ID
- meal_date: 급식 날짜
- school_code: 학교 코드

### 3. menu_item_ratings (개별 평점)
- user_id: 사용자 ID
- menu_item_id: 메뉴 아이템 ID
- rating: 개별 평점 (1-5점)

### 4. menu_item_rating_stats (평점 집계)
- menu_item_id: 메뉴 아이템 ID (외래키)
- avg_rating: 평균 평점
- rating_count: 평점 개수

### 5. menu_battle_daily (일별 배틀 결과)
- menu_item_id: 메뉴 아이템 ID
- battle_date: 배틀 날짜
- school_code: 학교 코드
- final_avg_rating: 최종 평균 평점
- final_rating_count: 최종 평점 개수
- daily_rank: 일별 순위

### 6. menu_battle_monthly (월별 배틀 결과)
- menu_item_id: 메뉴 아이템 ID
- battle_year: 배틀 연도
- battle_month: 배틀 월
- school_code: 학교 코드
- final_avg_rating: 최종 평균 평점
- final_rating_count: 최종 평점 개수
- monthly_rank: 월별 순위

## 🔄 배틀 계산 알고리즘

### 일별 배틀 (calculateDailyMenuBattleTest)
1. **데이터 조회**
   - 특정 날짜의 모든 메뉴 아이템 조회
   - 평점 집계 데이터 조인 (menu_item_rating_stats)
   - 급식 정보 조인 (meal_menus)
   - 조건: rating_count > 0 (평가가 있는 메뉴만)

2. **학교별 그룹화**
   - 같은 학교 내에서만 경쟁
   - schoolGroups[school_code] = [메뉴들...]

3. **순위 계산**
   - 각 학교별로 평균 평점 기준 내림차순 정렬
   - 순위 부여 (1위, 2위, 3위...)

4. **결과 저장**
   - menu_battle_daily 테이블에 저장
   - 기존 데이터 삭제 후 새로 삽입

### 월별 배틀 (calculateMonthlyMenuBattleTest)
1. **데이터 조회**
   - 특정 월의 모든 메뉴 아이템 조회 (1일~31일)
   - 평점 집계 데이터 조인
   - 급식 정보 조인

2. **학교별 그룹화**
   - 같은 학교 내에서만 경쟁
   - 같은 메뉴라도 날짜별로 개별 경쟁

3. **순위 계산**
   - 각 학교별로 평균 평점 기준 내림차순 정렬
   - 월별 순위 부여

4. **결과 저장**
   - menu_battle_monthly 테이블에 저장

## 🧪 테스트 모드 vs 프로덕션 모드
- **테스트 모드**: 상세한 디버그 로그 출력, 실제 DB 저장 안함
- **프로덕션 모드**: 최소 로그, 실제 DB 저장

## 🚨 주요 해결된 이슈들
1. **관계 참조 오류**: 명시적 외래키 관계명 사용
2. **테이블 참조 오류**: menu_item_rating_stats 테이블 사용
3. **스키마 캐시 오류**: DB에 외래키 관계 추가
4. **배포 경로 혼동**: apps/app/netlify/functions 경로 사용

## 📈 성능 최적화

- 평가가 있는 메뉴만 필터링 (rating_count > 0)
- 학교별 그룹화로 효율적인 순위 계산
- 배치 삽입으로 DB 부하 최소화

### 핵심 로직
1. **평점 입력/수정 → meal_rating_stats 업데이트**
2. **집계 프로세스 (트리거나 CRON)**
   - 특정 `battle_date` + `school_code` 행이 없으면 INSERT
   - 있으면 `avg_rating`, `rating_count` 재계산 후 UPDATE
3. **랭킹 계산**
   - 동일 region+school_type 그룹 내에서 `ORDER BY avg_rating DESC, rating_count DESC`
4. **프론트**
   - `GET /api/battle/meal?type=daily&date=YYYY-MM-DD&schoolType=고등학교`
   - `school_infos` 조인으로 지역/학교명 표시

## 🔧 주요 문제 해결 기록 (2025-07-27)

**문제:** 배틀 페이지에서 다른 날짜로 조회해도 항상 같은 데이터가 반환
**원인:** 배틀 API의 Supabase 쿼리에서 날짜 필터링이 제대로 작동하지 않음
**해결:**
```typescript

.eq('school_code', schoolCode)

// 수정 (올바른 코드)
.eq('school_code', schoolCode)  // 필터 순서 변경
.eq('battle_date', date)
```

=== 🔧 배틀 시스템 개선 (2025-07-29) ===

## 1️⃣ 메뉴 배틀 데이터 누락 문제 해결
**파일**: `apps/app/src/utils/battleCalculator.ts`

### 문제점
- 일별/월별 메뉴 배틀 계산 시 데이터 누락 발생
- 특히 모바일 환경에서 더 빈번하게 발생
- 2단계 프로세스(삭제 → 삽입)에서 삽입 실패 시 데이터 손실

### 수정 내용
#### 일별 메뉴 배틀 프로덕션 함수 개선
```typescript
// 기존 데이터 삭제
const { error: deleteError } = await supabase
  .from('menu_battle_daily')
  .delete()
  .eq('battle_date', date);

if (deleteError) {
  console.error('기존 데이터 삭제 실패:', deleteError);
  return { success: false, error: deleteError.message };
}

// 새 데이터 삽입 (재시도 로직 추가)
for (let attempt = 1; attempt <= 3; attempt++) {
  const { error: insertError } = await supabase
    .from('menu_battle_daily')
    .insert(battleResults);
    
  if (!insertError) {
    console.log(`✅ 일별 배틀 데이터 삽입 성공 (${attempt}번째 시도)`);
    break;
  }
  
  if (attempt === 3) {
    console.error('삽입 실패 (최대 재시도 초과):', insertError);
    return { success: false, error: insertError.message };
  }
  
  console.warn(`삽입 실패, 재시도 (${attempt}/3):`, insertError);
  await new Promise(resolve => setTimeout(resolve, 1000 * attempt));
}
```

#### 월별 메뉴 배틀 프로덕션 함수도 동일하게 수정
- 동일한 재시도 로직 및 에러 처리 추가
- 삭제 실패 시 전체 프로세스 중단

# 🔧 메뉴 배틀 UPSERT 최적화 - 불필요한 복합 기본키 제거 (2025-09-08)

## 📋 문제 상황
- `menu_item_id`가 이미 특정 날짜/학교의 급식메뉴 아이템을 고유하게 식별함
- 하지만 UPSERT에서 `(menu_item_id, battle_date, school_code)` 복합키를 사용하고 있었음
- 이는 논리적으로 불필요하며 성능상 비효율적

## 🔍 원인 분석
### menu_item_id의 의미
- `meal_menu_items.id`는 UUID로 전역적으로 고유함
- 이미 `meal_id`를 통해 특정 날짜/학교의 급식과 연결됨
- 따라서 `battle_date`, `school_code`를 추가로 기본키에 포함할 필요 없음

### 기존 구조의 문제점
```sql
-- 불필요한 복합 기본키
PRIMARY KEY (menu_item_id, battle_date, school_code)
```

## 🛠️ 해결 방법

### UPSERT onConflict 수정
**파일**: `apps/app/netlify/functions/utils/battleCalculator.js`

#### 일별 메뉴 배틀 함수
```javascript
// 기존 (불필요한 복합키)
.upsert(results, {
  onConflict: 'menu_item_id,battle_date,school_code'
});

// 수정 (menu_item_id만 사용)
.upsert(results, {
  onConflict: 'menu_item_id'
});
```

#### 월별 메뉴 배틀 함수
```javascript
// 기존 (불필요한 복합키)
.upsert(results, {
  onConflict: 'menu_item_id,battle_year,battle_month,school_code'

// 수정 (menu_item_id만 사용)

  onConflict: 'menu_item_id'
});
```
2. **불필요한 복잡성 제거**: 논리적으로 불필요한 복합키 사용 지양
3. **성능 고려**: 간단한 기본키 구조가 더 효율적

# 🔗 배틀 공유하기 링크 문제 해결 (2025-09-01)

## 📋 문제 상황
- **급식 공유하기**: `https://lunbat.com/?date=2025-09-01&school_code=7310207` ✅ 정상 작동
- **배틀 공유하기**: `https://lunbat.com/battle?date=2025-09-01&school_code=7310207` ❌ 문제 발생
  - 로그인 화면이 뜨지 않고 바로 배틀화면이 뜸
  - 배틀 공유하기 URL에서 battle 데이터가 없음

## 🔍 원인 분석
1. **로그인 체크 순서 문제**: URL 파라미터 처리보다 로그인 체크가 먼저 실행됨
2. **의존성 문제**: URL 파라미터 처리가 `user` 의존성에 의존하여 로그인되지 않은 상태에서 실행되지 않음
3. **데이터 로딩 실패**: 로그인 후에도 배틀 데이터가 제대로 로드되지 않을 수 있음

## 🛠️ 해결 방법

### 1. URL 파라미터 처리 순서 변경
**파일**: `apps/app/src/app/battle/page.tsx`

#### Before (문제 있는 코드)
```typescript
// 사용자 인증 상태 체크 - 배틀 페이지 접근 제어
useEffect(() => {
  // 로그인 체크 로직...
}, [user, userLoading, userError, router]);

// URL 파라미터 처리 (user 의존성으로 인해 로그인 후에만 실행)
useEffect(() => {
  // URL 파라미터 처리...
}, [user]); // user 의존성 때문에 로그인 전에는 실행 안됨
```

#### After (수정된 코드)
```typescript
// URL 파라미터 처리를 가장 먼저 실행 (로그인 상태 무관)
useEffect(() => {
  if (typeof window === 'undefined') return;
  try {
    const params = new URLSearchParams(window.location.search);
    const dateParam = params.get('date');
    const schoolCodeParam = params.get('school_code');
    
    console.log('🔗 URL 파라미터 확인:', { dateParam, schoolCodeParam });
    
    if (dateParam) {
      setSelectedDate(dateParam);
      console.log('📅 URL에서 날짜 설정:', dateParam);
    }
    
    // school_code는 로그인 후 처리하기 위해 임시 저장
    if (schoolCodeParam) {
      console.log('🏫 URL에서 school_code 감지, 로그인 후 처리 예정:', schoolCodeParam);
      sessionStorage.setItem('pending_school_code', schoolCodeParam);
    }
  } catch (err) {
    console.error('URL 파라미터 파싱 오류:', err);
  }
}, []); // 의존성 제거하여 즉시 실행

// 사용자 인증 상태 체크 (URL 파라미터 처리 후 실행)
useEffect(() => {
  // 로그인 체크 로직...
  
  // 로그인 완료 후 pending school_code 처리
  const pendingSchoolCode = sessionStorage.getItem('pending_school_code');
  if (pendingSchoolCode && user) {
    console.log('🔗 로그인 완료, pending school_code 처리:', pendingSchoolCode);
    handleUrlSchoolCode(pendingSchoolCode);
    sessionStorage.removeItem('pending_school_code');
  }
}, [user, userLoading, userError, router]);
```

### 2. 핵심 개선사항
1. **즉시 URL 파라미터 처리**: 로그인 상태와 무관하게 날짜 파라미터 즉시 적용
2. **school_code 지연 처리**: sessionStorage를 활용하여 로그인 후 school_code 처리
3. **로그 강화**: URL 파라미터 처리 과정을 상세히 로깅
4. **안전한 의존성 관리**: 각 useEffect의 의존성을 명확히 분리

## 🎯 수정 결과
✅ **URL 파라미터 우선 처리**: 로그인 전에도 날짜 파라미터가 즉시 적용됨
✅ **school_code 지연 처리**: 로그인 완료 후 자동으로 해당 학교 설정
✅ **배틀 데이터 자동 로딩**: 기존 useEffect 로직으로 자동 데이터 로딩 보장
